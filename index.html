Straight answers.

01Is it actually free?
Yes. The player carries a single ad on public embeds, and that is what pays for the bandwidth. Nothing is metered, nothing expires, and you are never asked for a card.
02Do I need an API key or an account?
No. There is no signup, no key and no domain allowlist. Build the URL, put it in an iframe, done. The only ids involved are TMDB's, which are public.
03Where does the content come from?
VidRift does not own or store the underlying media. It indexes and relays what is already publicly reachable, and metadata comes from TMDB. Takedown requests reach a human on Discord and are handled per title.

Documentation

Everything the embed can do.

The player is a single cross-origin iframe. Nothing to install, nothing to authenticate. Everything below is a URL parameter or a postMessage. That is the entire API surface.

Quick start

Paste this where you want the player. It is a complete, working, responsive embed.

Complete embed 
<div style="position:relative;padding-bottom:56.25%;height:0">
  <iframe src="https://embed.vidrift.in/embed/movie/1440098"
    style="position:absolute;inset:0;width:100%;height:100%;border:0"
    allowfullscreen allow="autoplay; fullscreen"></iframe>
</div>

Keep referrerpolicy at its default or strict-origin-when-cross-origin. Do not add a sandbox attribute: a sandboxed iframe cannot play. Fetching an /embed/* URL with a script instead of framing it returns 403.

URL structure

Two shapes. Anime is TV content under the hood, so it uses the TV shape with the show's TMDB id.

Routes 
https://embed.vidrift.in/embed/movie/{tmdb_id}
https://embed.vidrift.in/embed/tv/{tmdb_id}/{season}/{episode}

https://embed.vidrift.in/embed/movie/1440098     Drawn Together
https://embed.vidrift.in/embed/tv/1396/1/1       Breaking Bad S01E01
https://embed.vidrift.in/embed/tv/1429/1/1       Attack on Titan S01E01

Parameters

Every parameter is optional and validated server-side. Anything invalid is ignored rather than treated as an error, so a bad value never breaks playback.

ParameterValueWhat it does
titleTextShown on the preroll card while a source is being found. Without it the card falls back to the TMDB id until metadata loads.
brandText, ≤ 28 charsYour name, shown above the title on the preroll.
brandLogohttps URLYour logo, rendered 46px tall. Omit it and a monogram tile is drawn from the first letter of brand.
brandColor6-digit hexAccent for the wordmark rule, progress bar and glow. With or without the #.
mobileSheetstrueOn phones, delegates the Settings, Subtitles and Source panels to your own UI. See Mobile sheet.

Finding TMDB ids

Ids come from themoviedb.org. They are in the URL of any title page, and available through the TMDB API.

  • Movies: themoviedb.org/movie/1440098 → id is 1440098
  • TV and anime: themoviedb.org/tv/1396 → id is 1396

The home page builds the finished URL for you. Type an id into it, press Enter, and the real player loads.

White-label

While the player finds and warms a source it shows a preroll card. Add up to three query parameters and your logo, name and accent colour replace VidRift's on every embed.

  • brand: your name, plain text, max 28 characters.
  • brandLogo: an https URL to a PNG, SVG or JPG. A transparent background looks best. Omit it and the player draws a monogram tile from the first letter of brand.
  • brandColor: a 6-digit hex accent, with or without the #.
Fully branded embed 
https://embed.vidrift.in/embed/movie/1440098
  ?title=Drawn%20Together
  &brand=Acme%20Stream
  &brandLogo=https://acme.com/logo.svg
  &brandColor=%2300d1b2

A non-https logo, a colour that is not a hex triplet, or a logo URL that 404s all fall back silently to the default card.

Autoplay

The player always attempts autoplay, muted, as soon as a source is ready. That is what every browser allows without a user gesture, so there is nothing to enable. Sound comes on the moment the viewer interacts with the player.

Auto next episode

For TV and anime the player shows a five-second Up Next card 30 seconds before the end of an episode. It needs your page to say what the next episode is, and to swap the URL when the viewer confirms. Skip step one and the card never appears.

1 · Parent → Player, once the iframe has loaded 
iframe.contentWindow.postMessage({
  type: "vidrift:nextup-info",
  next: { season: 1, episode: 2 }
}, "https://embed.vidrift.in");
2 · Player → Parent, when the countdown ends or the viewer clicks Play Next 
window.addEventListener("message", (e) => {
  if (e.origin !== "https://embed.vidrift.in") return;
  if (e.data.type === "vidrift:nextup-play") {
    // e.data: { tmdbId, mediaType, season, episode } of the episode that just finished
    iframe.src = `https://embed.vidrift.in/embed/tv/${e.data.tmdbId}/${e.data.season}/${e.data.episode + 1}`;
  }
});

Messages

Every message is scoped to the https://embed.vidrift.in origin. Always check event.origin before trusting an incoming message, and always pass the origin as the second argument when sending one. All player messages carry tmdbId, mediaType, season and episode.

TypeDirectionWhen
vidrift:progressPlayer → ParentEvery 5 seconds while playing, after the first 5 seconds. Adds currentTime and duration.
vidrift:nextupPlayer → ParentOnce, 30 seconds before the end.
vidrift:nextup-playPlayer → ParentThe Up Next countdown finished or the viewer clicked Play Next.
vidrift:endedPlayer → ParentPlayback reached the end.
vidrift:mobile-panelPlayer → ParentA phone viewer opened a panel, with mobileSheets=true. Adds panel and options.
vidrift:resumeParent → PlayerSeek to currentTime in seconds. Safe to send before the video is ready; it is applied once it is.
vidrift:quality-preferenceParent → PlayerPin a rendition: label is "1080p", "720p", "480p", "360p" or "Auto".
vidrift:nextup-infoParent → PlayerEnable the Up Next card with next: { season, episode }. Send next: null to hide it.
vidrift:mobile-optionParent → PlayerReply to a mobile-panel message with the chosen option and value.
One listener, every event 
window.addEventListener("message", (e) => {
  if (e.origin !== "https://embed.vidrift.in") return;
  switch (e.data.type) {
    case "vidrift:progress": save(e.data.tmdbId, e.data.currentTime); break;
    case "vidrift:ended":    markWatched(e.data.tmdbId);         break;
  }
});

Mobile sheet

On phones the player opens its own bottom sheet for Settings, Subtitles and Source. If you would rather render that sheet in your site's own UI, add ?mobileSheets=true to the URL and answer the panel message. Leave the flag off and no listener is needed.

Delegated sheet 
window.addEventListener("message", (e) => {
  if (e.origin !== "https://embed.vidrift.in") return;
  if (e.data.type !== "vidrift:mobile-panel") return;
  // e.data.panel: "settings" | "subtitles" | "source"
  // e.data.options: [{ option, value, label, group }]  — "settings" mixes quality and speed
  const chosen = await showYourSheet(e.data.options);
  iframe.contentWindow.postMessage({
    type: "vidrift:mobile-option",
    option: chosen.option, // use the chosen option's own field, not the panel name
    value: chosen.value
  }, "https://embed.vidrift.in");
});

Notes & limits

  • hls.js ships inside every embed page. There are no dependencies to add on your side.
  • Mobile-responsive, with iOS Safari fullscreen via webkitEnterFullscreen.
  • Embeds are rate-limited per client. Normal traffic never touches the limit; scripted bulk fetching does.
  • Public embeds carry a single ad. That is what pays for the bandwidth.
  • Metadata and artwork come from TMDB. VidRift is not endorsed or certified by TMDB.
  • Issues and takedown requests reach a human on Discord.
